# Перенос pre-prod → prod и эксплуатация

Назад: [[01 - Чек-лист prod-сервера]] · Обзор: [[00 - Обзор]]

## Перенос pre-prod → prod (docs/26, C-00…C-13)

### Гейт C-00 — без него перенос не начинается

- [ ] На prod выполнены все шаги [[01 - Чек-лист prod-сервера]] (сид и приёмку делать можно — перенос заменит базу)
- [ ] В журнале `docs/27` нет строк с prod-статусом ⬜ (кроме самих C-шагов)
- [ ] Одинаковый SHA: последняя `status=ok` в `deploy-history.log` на обоих серверах
- [ ] `S3_ACCESS_KEY` / `S3_SECRET_KEY` в prod-`.env` = pre-prod (D-04)
- [ ] MAGSpace на prod с теми же `Employee.id` (D-05)
- [ ] `DIRECTORY_RECONCILE_MODE=report` на первые дни
- [ ] SSO-клиент: origin `https://mymag.magtrans.eu` добавлен
- [ ] Известно, как попасть на prod по SSH, чтобы положить файлы (Q-03)
- [ ] Репетиция C-02…C-09 на prod со свежим бэкапом pre-prod
- [ ] Окно вне кронов: не 03:30 (бэкап, чистка токенов), не 07:00–07:20 (SLA, watchdog, алерт машин)

## Регулярная эксплуатация

| Что | Когда | Зачем |
|---|---|---|
| Ручной бэкап (`systemctl start magguarantee-backup.service`) | перед каждым выкатом с миграцией | CI бэкап не делает, миграции только вперёд |
| `magguarantee-restore-test` | раз в квартал | проверка, что бэкапы восстанавливаются |
| `systemctl list-timers magguarantee-backup.timer`, heartbeat в Kuma | регулярно | таймер мог тихо перестать запускаться |
| `cp` юнитов + `systemctl daemon-reload` | после `git pull`, меняющего `infra/systemd` | юниты — копии, а не ссылки на чекаут |
| `docker exec caddy caddy reload --config /etc/caddy/Caddyfile` | после `git pull`, меняющего фрагмент Caddy (если `import`) | CI этого не делает |
| `git status` на сервере | всегда пустой | никаких хотфиксов в чекауте |
| Правка `.env` | по необходимости | строкой в журнале `docs/27` (описанием, не значением) |

## Откат (docs/23 «Откат»)

| Случай | Как |
|---|---|
| Код | `infra/scripts/magguarantee-rollback <sha>` — пересборка, 5–10 минут |
| Миграция | не откатывается — только новой миграцией. Колонки добавлять nullable, удалять отдельным релизом |
| Данные | `infra/scripts/magguarantee-restore-db` + архив MinIO **того же вечера** |

## Чего нет в доках, но стоит сделать

| Что | Зачем |
|---|---|
| Swap 2–4 GB | сборка Next.js на сервере — пик памяти; на staging swap = 0 |
| `timedatectl set-timezone Europe/Warsaw` | таймер бэкапа идёт в 03:30 по времени сервера, а окна кронов в C-00 — по Варшаве |
| Мониторинг диска (Kuma Push при `df` > 80%) | в `docs/18` упомянут, не реализован; в `backups/` 7 дней полных tar MinIO |
| Снапшоты хостера / недельные и месячные бэкапы (GFS) | не реализованы, сейчас RPO 24 ч |
| Проверить, что `unattended-upgrades` реально включён, решить про авто-ребут | ставится пакетом, но настройку стоит проверить |

## Известные хвосты (docs/23)

- Откат медленный: сборка на сервере. Переход на ghcr сделает его подменой тега.
- Админ в сиде захардкожен (`seed.prod.ts`) — для передачи системы лучше вынести в env.
- MinIO архивируется полным tar каждый раз — при росте до гигабайтов перейти на `rclone sync`.
- Почта зависит от OAuth-клиента в личном GCP-проекте (D-03) — перенести в проект фирмы и перевыпустить токен.
